---
name: Unknown outreach sends
description: Fail-closed rules for provider responses that do not prove whether an outreach email was accepted.
---

Keep an immutable prospect/campaign-sequence send claim whenever the provider outcome is ambiguous. Transport failures, timeouts, conflicts, and server or gateway errors require employee review; they must never release the claim or return the message to an automatically sendable state. An explicit SendGrid HTTP 429 response is a proven provider throttle and may release the attempt for paced retry; a timeout while waiting for a response remains ambiguous. Reconcile late provider events using a stable key written before dispatch.

**Why:** An HTTP response can be lost or generated by an intermediary after the provider accepted the message. Releasing the sequence guard on uncertain evidence can create a duplicate email.

**How to apply:** Release a claim only when evidence proves the provider never accepted the request. Provider activity showing bounce, block, or drop is an accepted attempt and must suppress the address, not retry it. A received 429 response should honor provider pacing and retry without lowering the daily goal. Timeouts, missing records, and unknown statuses stay blocked; processed, deferred, and delivered evidence resolves review without redispatch.
