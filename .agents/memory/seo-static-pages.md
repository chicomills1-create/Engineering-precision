---
name: Static SEO page generation
description: How the programmatic SEO pages for apex-grid work and dev-server gotchas
---
- ~5,194 static pages (hub + 50 states + state×service + 18 curated cities + city×service + ~4,864 Census-derived lite city pages + 6 blog posts) are generated by `pnpm --filter @workspace/apex-grid run seo:generate` into `public/locations/` and `public/blog/`; it also rebuilds sitemap.xml (~5,200 URLs, ~85 MB of static HTML). Data lives in `seo/states/*.ts` (StateData), `seo/cities/*.ts` (curated CityData), `seo/cities-directory.json` (Census pop≥5k places; lite pages inherit only state-level facts — never invent city-specific claims), and `seo/blog.ts`. City slugs must never collide with service slugs — the generator asserts this and skips lite pages that collide with curated cities.
- **Why static:** the site is a Vite SPA (invisible to Googlebot); static HTML in public/ ships in the build output and is crawlable.
- **Gotcha:** Vite dev caches the public-dir file list — after regenerating pages, restart the web workflow or deep paths serve the SPA fallback. A dev-only vite plugin (`staticDirIndex`) rewrites `/locations/**/` and `/blog/**/` directory URLs to index.html — any NEW top-level static dir must be added to its regex or it silently serves the SPA.
- **How to apply:** after editing state data, run seo:generate, restart web workflow, and republish for production.
